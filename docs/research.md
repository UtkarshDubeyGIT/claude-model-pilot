# Research notes

Reviewed 21 October 2026. Local development and validation target: Claude Code **2.1.303**. This is an early implementation, not evidence of production reliability or measured savings.

## Supported integration

A native Claude Code mod is the appropriate integration. It can read draft prompts, render recommendations, and override the model and effort of an outgoing request. A legacy `UserPromptSubmit` hook can provide context or block a prompt, but has no documented output field that changes the model. [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference), [legacy hooks reference](https://code.claude.com/docs/en/hooks).

Mods are ordinary plugins with a manifest and a `hooks/hooks.json` module entry. Claude Code loads JavaScript or TypeScript directly. Use `claude plugin validate` for the host's static checks and `claude plugin test` for host-level tests. The declarations generated by the installed CLI take precedence over online examples; the public GitHub declarations examined during research were older than the installed version. [Create a mod](https://code.claude.com/docs/en/plugins/mods/create).

## Routing boundaries

`prompt.edit` observes typing; its input contains the previous draft and edit, while its result contains the updated draft. Keep this path fast and local. Associate routing with `turn.start` and its turn identifier. `prompt.submit.turnId`, when present, refers to a turn already running when the prompt arrived, so it must not be mistaken for the new turn. [Published type declarations](https://github.com/anthropics/claude-code/blob/main/mods/types/claude-code.d.ts).

`turn.step` is a streaming middleware event. It permits changing `model` and `effort` while forwarding the response stream. It also fires for subagents, distinguished by `agentId`. A routing choice should remain fixed across the requests of a turn; incidental tool results are not a reason to repeatedly reconsider the model. Read actual usage from response results rather than estimating token savings from the chosen model's name. [React to events](https://code.claude.com/docs/en/plugins/mods/events).

The prompt-edit execution budget is particularly short. Render-site availability differs across terminal, Desktop, and VS Code. Mods can be disabled by user or organization settings, and model availability and effort limits may be constrained by the deployment. Test the supported surface and installed version rather than assuming every client behaves identically. [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference), [model configuration](https://code.claude.com/docs/en/model-config).

## Model calls and economics

An optional small-model classifier can use the mod API and the session's existing credentials. These requests consume the user's plan or provider budget. Current documentation describes a structured `model.complete` result whose `isAnswered` field distinguishes an answer from an unsuccessful API request; code must also handle rejected calls. A classifier failure should retain the current model. [Use the mods API](https://code.claude.com/docs/en/plugins/mods/api).

Each model has its own prompt cache. Switching can require processing the full conversation again, so a cheaper model can cost more for a short detour in a long session. Effort changes also invalidate cache on many configurations. The documented exceptions for current 5.5 models depend on provider and configuration; lower effort must not be advertised as universally cache-preserving. [Prompt caching](https://code.claude.com/docs/en/prompt-caching).

A cheaper token rate is not fewer tokens. Lower effort may reduce generated reasoning, while model switching primarily changes the rate and capability. Subscription limits, API dollars, latency, and task quality are separate outcomes. Claude Code's cost display is an estimate and can reflect configured organization rates; authoritative billing remains with the provider. [Manage costs](https://code.claude.com/docs/en/costs).

## Production caveats

- No measured quality improvement, token reduction, or financial savings is claimed.
- Local CLI checks and simulated routing tests do not establish performance on real enterprise tasks.
- Keyword rules cannot reliably understand every language, attachment, project, or continuation. Ambiguous inputs should preserve the current model.
- Manual choices, ongoing planning, and difficult follow-ups deserve stronger protection than an isolated simple prompt.
- Keep the model catalog and provider policy configurable. Aliases and capability support change over time.
- Validate organization policy, cache behavior, and cancellation paths before enabling automatic routing for a team.

## Jev adapter

TypeSafe Jev is the default System One decision provider. Jev accepts structured state plus typed questions at `POST https://api.typesafe.ai/v1/systemone`; authentication is `Authorization: Bearer <key>`. Use `TYPESAFE_API_KEY` and optional `TYPESAFE_MODEL` at process startup. [Official quickstart](https://docs.typesafe.ai/introduction/quickstart), [API schema](https://api.typesafe.ai/openapi.json).

The adapter uses two independent Choice questions: task complexity and independence from previous context. It validates labels, probability distributions and confidence before passing a recommendation to the existing continuity policy. TypeSafe confidence measures concentration of a distribution; it is not a demonstrated probability that the routing decision is correct. Thresholds require workload evaluation. [Confidence](https://docs.typesafe.ai/confidence).

Native Claude Code HTTP requests expose no per-request abort option in the inspected types. A host timer limits the adapter's wait to 1.5 seconds; an underlying late request can continue and incur cost. Subsequent live evaluations are recorded in [validation](validation.md) and [benchmark results](benchmark-results.md); they do not establish broad accuracy or savings.
